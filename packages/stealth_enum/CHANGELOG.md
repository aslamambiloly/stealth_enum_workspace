## 2.2.0

### Security & Hardening
* Added `key: String?` parameter to `@StealthEnum(key: '...')` for custom keyed HMAC derivation.
* Hashing upgraded from linear FNV-1a to **keyed HMAC-SHA256**: satisfies the strict avalanche criterion and eliminates XOR differential attacks (`valA ^ valB` no longer cancels the key or enum name).
* Added range validation to `@StealthValue`: values must be positive 32-bit unsigned integers (`0x0` to `0xFFFFFFFF`), requiring `>= 0x1000` to prevent low sequential jump tables.
* Added compile-time validation enforcing private enums (leading `_`) to ensure Dart AOT tree-shaking.
* Added compile-time check preventing constant names from colliding with generated extension type members.

> **Migration from 2.0.x / 2.1.0:** The HMAC-SHA256 upgrade modifies the derived integer values for un-annotated constants. If you persisted 2.0.x / 2.1.0 raw integer values into databases or storage, freeze those values using `@StealthValue(0x...)` before regenerating.

## 2.1.0

### New Features
* Added `@StealthValue(int value)` annotation: assign explicit, frozen raw integer values to specific enum constants (e.g., for backwards compatibility with backend API contracts or databases).
* Decoupled `toJson()` and `fromJson(int)` from `generateLabel`: integer-based serialization helpers are now generated by default on all extension types with zero string footprint.
* Deterministic 32-bit FNV-1a hashing replaces SDK-dependent `hashCode`: constant values are generated using `(seed ?? 0xDEADBEEF) ^ fnv1a(publicName) ^ fnv1a(fieldName)`. Each constant is computed independently—inserting, removing, or reordering enum constants no longer shifts the values of existing constants.
* Empirical verification: Side-by-side verification script (`scripts/verify_aot_strings.sh`) compares standard enum vs StealthEnum binaries, confirming that standard enums leak their identifiers while StealthEnum leaves zero strings in AOT output.
